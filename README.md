Part 1. 팀원 공유용 실전 Git/GitHub 협업 가이드 (수정본)2. 우리가 매일 반복할 Git 실전 사이클새로운 기능을 코딩하고 최종 완성본에 합치기까지의 전체 과정입니다. VS Code 터미널과 슬랙, 깃허브를 오가며 아래 순서대로 진행합니다.1.1단계: 내 작업 브랜치 만들고 이동:내 전용 비밀 폴더를 만들고 들어갑니다.

git checkout main

git checkout -b feature/본인기능명 -> 개인브랜치 생성


2.2단계: 코딩 후 내 폴더에 업로드 (Push):미완성이어도 퇴근 시 반드시 실행하여 코드 유실 방지.

git add .
git commit -m "feat: 담당 기능 구현"
git push origin feature/본인기능명  -> 이 3가지 기능이 vscode에서 한번에 가능합니다 대신 밑에 내용 확인하고 커밋&푸쉬 부탁드립니다.

⚠️ VS Code 소스 제어 창을 쓸 때 '딱 하나' 조심할 점
마우스로 클릭할 때 가장 많이 하는 실수가 "내가 지금 무슨 브랜치방에 들어와 있는지 모르고 누르는 것"입니다.

확인 방법: 커밋/푸쉬를 누르기 전에, VS Code 맨 왼쪽 아래 화면 구석을 보면 현재 내 브랜치 이름(예: feature/login)이 영문으로 적혀 있습니다.

거기에 main이 아니라 내 전용 브랜치 이름이 잘 떠 있는지 눈으로 확인하고 마우스로 커밋/푸쉬를 누르면 안전하게 내 방으로만 올라갑니다.


3.3단계: GitHub에서 PR 생성 후 슬랙 공지:
★ 셀프 머지 절대 금지! 슬랙 알림 필수.깃허브 웹사이트 접속 ➔
 초록색 [Compare & pull request] 클릭 ➔ 
내용 작성 후 제출(PR 생성)[슬랙 공지]: 슬랙 공지방에 **"feature/로그인 작업 완료하여 PR 올렸습니다! 검토 부탁드립니다! [링크]"**라고 메시지를 남깁니다.

4.4단계: 팀원의 코멘트(Comment) 검토 및 반영:
동료의 피드백을 반영하는 핵심 소통 단계.슬랙 알림을 본 다른 팀원들이 깃허브 PR 페이지의 Files changed 탭에서 코드를 확인합니다.보완이 필요한 부분에 **코멘트(Comment)**를 달아주면, 작성자는 코드를 수정하여 다시 Push합니다. 수정할 내용이 없다면 검토하시고 이상없음 등으로 코멘트 달고 머지 해주시면 될것 같습니다.  (PR은 자동으로 업데이트됩니다.)검토자 1인 이상이 코드에 문제가 없음을 확인하고 **[Approve(승인)]**를 누릅니다.

5.5단계: 최종 합치기 (Merge):통합담당 또는 교차 검토자가 최종 승인 후 실행.승인이 완료되면, 통합담당 또는 다른 팀원이 깃허브에서 초록색 [Merge pull request] 버튼을 눌러 main 방에 합칩니다.

6.6단계: 로컬 내 컴퓨터 main 업데이트 (Pull):인터넷 main 방의 최신 코드를 내 노트북으로 다운로드.Bashgit checkout main
git pull origin main

7.7단계: 내 작업 폴더로 복귀 후 메인 내용 주입 (Local Merge):내 개인 폴더도 최신 상태로 만들어 코드가 꼬이는 것을 방지.Bashgit checkout feature/본인기능명
git merge main


Part 2. 프로젝트 제안서:
 5. 팀 협업 및 개발 규칙(최종 수정본)

5. 팀 협업 및 개발 규칙 (Git/GitHub)本 팀은 AI 기반 바이브 코딩(Vibe Coding) 환경에서 발생할 수 있는 복잡한 PostgreSQL 데이터 모델 충돌을 미연에 방지하고, 소스코드의 안정성을 유지하기 위해 아래와 같은 개발 규칙을 정의하고 엄격히 준수한다.

5.2 작업 프로세스 및 코드 통합(Merge) 규칙모든 팀원은 하나의 기능을 완성할 때마다 아래 프로세스를 거쳐 코드를 안전하게 통합한다.1단계 (작업 브랜치에서 깃허브로 Push): 내 브랜치에서 작업 완료 후 git add ., git commit, git push origin feature/내-브랜치를 수행하여 원격 저장소에 코드를 업로드한다.

2단계 (GitHub PR 생성 및 슬랙 공지): GitHub 저장소에서 main 브랜치를 대상으로 PR을 생성한 후, 팀 공용 슬랙 공지방에 해당 PR 링크와 함께 코드 리뷰 요청 메시지를 즉시 게시한다.

3단계 (팀원 코멘트 검토 및 교차 리뷰): 슬랙 공지를 확인한 팀원들은 해당 PR의 소스코드를 교차 검증한다. 수정이나 보완이 필요한 경우 GitHub 코멘트(Comment) 기능으로 의견을 남기며, 개발자는 코멘트를 반영해 코드를 수정하고 재푸쉬한다. 로컬 서버 실행(runserver) 시 에러가 없고 기능이 정상 작동함을 확인한 검토자가 최종 승인(Approve)을 처리한다.

4단계 (최종 코드 통합 - Merge): (셀프 머지 금지) 코드 리뷰 결과 결함이 없고 1인 이상의 승인을 획득하면, 통합담당 또는 지정된 교차 검토자가 GitHub 웹에서 최종 Merge를 집행한다.

5단계 (로컬 main 브랜치 최신화 - Pull): GitHub에서 머지가 완료되면 모든 팀원은 로컬 터미널에서 main 브랜치로 이동 후 git pull origin main을 실행하여 최신 코드를 동기화한다.

6단계 (작업 브랜치 이동 후 메인 코드 병합 - Local Merge): 다시 본인이 개발하던 기능 브랜치로 이동하여 최신 main 브랜치의 내용을 병합(git merge main)함으로써 로컬 작업 공간을 최신 상태로 유지한다.
